# Разделы 5–6. Сортировка и поиск

## Сортировки

| Реализация | Сложность | Память | Устойчива |
|---|---|---|---|
| `MergeSort` | O(n log n) всегда | O(n) | да |
| `QuickSort` | O(n log n) в среднем, O(n²) в худшем | O(log n) | нет |
| `CountSort` | O(n + k) | O(n + k) | да |
| `RadixSort` | O(d·(n + k)), для int четыре прохода по байтам | O(n + k) | да |
| `HeapSort` | O(n log n) всегда | O(1) | нет |

Сортировать сравнением быстрее O(n log n) нельзя — это доказывается через дерево решений.
`CountSort` и `RadixSort` обходят границу, потому что не сравнивают, а используют ключ как адрес.

`MainSort` печатает фактическое число операций и проверяет результат на упорядоченность.

## Поиск

`BinaryIndexSearch` ищет по индексу в отсортированном списке, `BinaryNaturalSearch` — по
монотонной функции на целых, `BinaryRealSearch` — на вещественных с заданной точностью.
Все за O(log n) против O(n) у перебора.

## Задание

В `QuickSort` намеренно оставлена ошибка, помеченная в JavaDoc. Прогон `MainSort` показывает её
сразу: стратегия Хоара выдаёт неотсортированный массив. Тест `halfwayQuickSortOrdersElements`
отключён — снимите `@Disabled` и почините.

## Практика по мастер-теореме

1. Разложите сортировку `[7, 8, 2, 0, 5, 2, 7, 0]` на дерево. Для каждого
   внутреннего узла размера `m` запишите `m` переносов в две половины и `m`
   записей в результат слияния. В листе размера 1 счётчик не увеличивается.
2. Просуммируйте работу по уровням и запишите рекуррентность. Для степеней
   двойки `C(n) = 2C(n/2) + 2n`, `C(1) = 0` для счётчика. Для времени работы
   база имеет постоянную стоимость. Определите случай мастер-теоремы и
   сравните оценку с суммой по дереву.
3. Сверьте расчёт с `MergeSort` и `Counter`. Передайте `ArrayList`, чтобы
   обращение по индексу занимало постоянное время. Перед каждым запуском
   создайте новый счётчик и передайте `false` для параметра отладки.

Из корня репозитория на JDK 17:

```sh
mvn -B -pl 05-sorting-search -am -Dtest=MergeSortTest -Dsurefire.failIfNoSpecifiedTests=false test
```

Ожидаемый порядок для примера — `[0, 0, 2, 2, 5, 7, 7, 8]`. Для восьми
элементов три внутренних уровня дают по 16 операций, всего 48.
Второй случай мастер-теоремы даёт Θ(n log n).

| n | 1 | 2 | 4 | 8 | 16 |

| Счётчик | 0 | 4 | 16 | 48 | 128 |
