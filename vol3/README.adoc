= Разделы 5–6. Сортировка и поиск

== Сортировки

|===
| Реализация | Сложность | Память | Устойчива

| `MergeSort` | O(n log n) всегда | O(n) | да
| `QuickSort` | O(n log n) в среднем, O(n²) в худшем | O(log n) | нет
| `CountSort` | O(n + k) | O(n + k) | да
| `RadixSort` | O(d·(n + k)), для int четыре прохода по байтам | O(n + k) | да
| `HeapSort` | O(n log n) всегда | O(1) | нет
|===

Сортировать сравнением быстрее O(n log n) нельзя — это доказывается через дерево решений.
`CountSort` и `RadixSort` обходят границу, потому что не сравнивают, а используют ключ как адрес.

`MainSort` печатает фактическое число операций и проверяет результат на упорядоченность.

== Поиск

`BinaryIndexSearch` ищет по индексу в отсортированном списке, `BinaryNaturalSearch` — по
монотонной функции на целых, `BinaryRealSearch` — на вещественных с заданной точностью.
Все за O(log n) против O(n) у перебора.
