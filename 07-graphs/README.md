# Раздел 8. Графы

| Пакет | Что внутри |
|---|---|
| `graph` | граф списками смежности, вершины, рёбра, веса |
| `graph.algorithms` | обходы в глубину и ширину, поиск цикла, Дейкстра, муравьиный алгоритм |
| `graph.loader` | разбор текстового формата |

## Формат файла графа

Рёбра записываются подряд, без переводов строк: `{исходная,целевая,вес}`. Вес необязателен и по
умолчанию равен единице. Пример: `{a,b,1}{b,c}{c,a,5}`. Примеры лежат в `src/main/resources`.

## Сложности

| Алгоритм | Сложность |
|---|---|
| Обход в глубину и в ширину | O(V + E) |
| Дейкстра на приоритетной очереди | O(E log V) |

Дейкстра требует неотрицательных весов: отсечение по посещённым вершинам иначе даёт неверный
ответ молча. Муравьиный алгоритм — эвристика: точного ответа не гарантирует, зато переносится
на задачи, где точный перебор невозможен.

## Практика. Компоненты сильной связности

Дуги примера — `A→B`, `B→C`, `C→A`, `B→D`, `C→D`, `D→E`, `E→D`,
`E→F`. Добавьте вершину `G` отдельно через `Graph.addVertex`.

1. Обойдите исходный граф в глубину. Начинайте DFS из каждой ещё
   не посещённой вершины. Записывайте вершину **после** обработки соседей.
   При алфавитном порядке вершин и соседей получится `F E D C B A G`.
2. Постройте обратные списки смежности. Заведите массив номеров компонентов
   со значением `-1` для каждой вершины. Перебирайте вершины в порядке
   `G A B C D E F`. При встрече вершины с номером `-1` начните из неё DFS
   по обратным дугам и присвойте всем новым вершинам один номер компоненты.
3. Для каждой исходной дуги сравните номера компонентов её концов.
   Если номера различаются, добавьте направленную пару в множество дуг
   конденсации. Объясните, почему `B→D` и `C→D` дают одну пару.

Решение и демонстрация находятся в пакете `ru.mifi.practice.vol5.graph.algorithms`.
Для запуска из корня репозитория на JDK 17 выполните

```sh
mvn -B -pl 07-graphs -am verify
java -cp 07-graphs/target/classes ru.mifi.practice.vol5.graph.algorithms.StrongComponentsDemo
```

Ожидаемый вывод

```text
Компоненты: {G}, {A, B, C}, {D, E}, {F}
Дуги конденсации:
{A, B, C} → {D, E}
{D, E} → {F}
```

Проверьте также пустой граф, вершину с петлёй, ориентированный цикл и DAG.
В DAG каждая вершина образует собственную компоненту. Реализация использует
рекурсивный DFS, поэтому глубина стека зависит от длины пути обхода.

## Сравнение числа операций кратчайшего пути (AADS-12)

В `DijkstraShortestPath`, `BellmanFordShortestPath` и `FloydWarshallShortestPath`
есть перегрузки `distances(..., Counter counter)`. Старые вызовы без счётчика
сохранены. Создайте счётчик через `Counter.create()`, передайте в поиск и
прочитайте `counter.count()`. Повторные вызовы **накапливают** значение;
для нового независимого замера вызовите `counter.reset()`.

Единица подсчёта — **одна попытка улучшить расстояние**: алгоритм складывает
длины двух частей пути и сравнивает кандидата с известным расстоянием.
Неуспешная попытка тоже считается. Это согласованное решение R2652 в aNaL.

- Дейкстра считает такие попытки для дуг к ещё не посещённым вершинам.
- Беллман — Форд считает их во всех выполненных проходах, включая
  заключительную проверку отрицательного цикла. Ранний выход не добавляет
  невыполненных проходов.
- Флойд — Уоршелл считает кандидатов `i→k→j`, только если обе части пути
  достижимы. Нулевые пути вершины в себя участвуют в этих попытках.

Инициализация таблиц, загрузка прямых дуг Флойда, пропуск недостижимых
путей, работа очереди, обход коллекций и прочие служебные действия в число
не входят. Поэтому счётчик показывает объём работы по релаксации, а не
все инструкции, время выполнения или полную асимптотическую сложность.
При большом числе попыток учитывайте, что существующий `Counter` хранит `int`.
Дейкстра применим к неотрицательным весам, Беллман — Форд допускает
отрицательные дуги и отклоняет достижимый отрицательный цикл; Флойд в этой
реализации не проверяет отрицательные циклы.

Для сравнения **одной задачи** Флойд запускается один раз для всех пар,
а Дейкстра и Беллман — Форд — от каждой вершины, с накоплением счётчиков.
Пример содержит дуги `A→B=1`, `A→C=10`, `B→C=2`; вершины добавлены
в порядке `A,B,C`. Расстояние `A→C` получается 3. Демонстрация сверяет
все три полные таблицы; до каждой вершины от неё самой расстояние 0,
обратные пути недостижимы.

```sh
mvn -B -pl 07-graphs -am verify
java -cp 07-graphs/target/classes:00-commons/target/classes \
  ru.mifi.practice.vol5.graph.algorithms.ShortestPathsComparison
```

Ожидаемый вывод:

```text
Все пары: A→B=1, A→C=3, B→C=2; обратные пути недостижимы.
Дейкстра: 4
Беллман — Форд: 8
Флойд — Уоршелл: 10
```

Для Дейкстры это 3 попытки от A, 1 от B и 0 от C. Для Беллмана — Форда
получается 6, 2 и 0: после прохода, нашедшего расстояния, следующий проход
подтверждает отсутствие улучшений. Для Флойда промежуточные вершины A, B
и C дают 3, 4 и 3 попытки. Числа зависят от графа и порядка обхода, особенно
из-за раннего выхода Беллмана — Форда; это пример, а не универсальный рейтинг.
