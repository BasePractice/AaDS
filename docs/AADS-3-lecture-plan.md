# AADS-3. План лекции «Многопоточность в Java»

План на утверждение заказчиком. Презентация и модуль практики делаются только после утверждения.

## Формат и стиль

Ориентир — `docs/АиСД4.pptx` (референс AADS-1) и принципы AADS-2:

- шрифт Fira Code во всех текстовых фрагментах, включая подписи на схемах;
- каждый раздел открывается титульным слайдом с названием темы;
- подача послайдовая, потезисная: слайд 1 — тема, слайд 2 — тезис 1, слайд 3 — тезисы 1–2,
  слайд 4 — тезисы 1–3 и так далее; список из N тезисов раскрывается на N+1 слайде;
- каждое объяснение строится из трёх частей: теория (текст) → графика (схема потоков,
  таймлайн, диаграмма состояний) → пример кода из практики;
- примеры рассчитаны на слабо подготовленного студента: опираются только на пройденное
  (занятия 1–16), новых знаний вне лекции не требуют;
- слайд-маркер «Programming Time!» перед переходом к практике.

Объём — одно занятие №17, ориентировочно 90–110 слайдов (сравнимо с занятиями 5–8 курса).

## Разделы лекции

### 1. Зачем несколько потоков (6–8 слайдов)

Тезисы: один поток — одна очередь команд; процессы против потоков; параллелизм (несколько ядер)
против конкурентности (переключение); где многопоточность ускоряет, а где мешает.

Графика: таймлайн одного потока против двух; схема «процесс → потоки → общая куча».

Код: `Thread` с `Runnable`, `join`, `isAlive`, `Thread.getState`; демо двух потоков,
печатающих в общий `System.out`.

### 2. Потоки в Java (10–12 слайдов)

Тезисы: создание `Thread` и `Runnable`, `start` против `run`; жизненный цикл и состояния
`NEW/RUNNABLE/BLOCKED/WAITING/TIMED_WAITING/TERMINATED`; `sleep`, `join`, `interrupt` и
кооперативная отмена; `UncaughtExceptionHandler`; `ThreadLocal`.

Графика: диаграмма состояний потока; пошаговый таймлайн `start → run → join`.

Код: два потока с `join`; корректная отмена через `interrupt`; `ThreadLocal`-счётчик.

### 3. Гонки данных и JMM (10–14 слайдов)

Тезисы: interleaving операций; гонка на `counter++` (чтение–изменение–запись); что видно
одному потоку не видно другому; happens-before, volatile, переупорядочивание; deadlock,
livelock, starvation — три классические проблемы (коллизии с проблемами).

Графика: пошаговая таблица двух потоков, пишущих в одну ячейку — с числами, как в примере
полиномиального хеша из занятия 6; схема happens-before.

Код: сломанный счётчик на двух потоках (воспроизводимая гонка с большим числом итераций);
починенный `volatile` (только видимость) и атомарный (следующий раздел).

### 4. Мониторы и synchronized (8–10 слайдов)

Тезисы: intrinsic lock каждого объекта; метод против блока; reentrancy; wait/notify/notifyAll
внутри монитора; зачем `wait` в цикле.

Графика: схема «объект с замком, поток держит, второй ждёт»; таймлайн producer/consumer.

Код: producer–consumer на `synchronized` + `wait/notify` через `ArrayBlockingQueue`-подобный
кольцевой буфер (связь с занятием 2).

### 5. Примитивы синхронизации из java.util.concurrent (10–12 слайдов)

Тезисы: `Lock`/`ReentrantLock` против монитора, `tryLock`, `Condition`; `ReadWriteLock`;
`Semaphore`; `CountDownLatch`, `CyclicBarrier`, `Exchanger`, `Phaser` — по одному случаю
применения на каждый.

Графика: сравнение замков таблицей; схема «N потоков у барьера».

Код: ограничение доступа к ресурсу семафором; барьер для одновременного старта;
`ReentrantLock` с `tryLock` без дедлока.

### 6. Атомарные операции (8–10 слайдов)

Тезисы: CAS — compare-and-swap, аппаратная поддержка; классы `AtomicInteger`, `AtomicLong`,
`AtomicReference`, `LongAdder`; когда атомики выигрывают у замков, а когда нет; ABA-проблема.

Графика: пошаговая схема CAS (ожидаемое → новое, успех/отказ); сравнение `AtomicInteger`
и `LongAdder` под contention.

Код: счётчик из раздела 3, починенный `AtomicInteger`; `LongAdder` для статистики;
CAS-цикл `compareAndSet`.

### 7. Потокобезопасные коллекции (8–10 слайдов)

Тезисы: почему `ArrayList`/`HashMap` ломаются (связь с занятием 6 — рост таблицы);
`synchronized`-обёртки; `ConcurrentHashMap` (сегменты, CAS-вставка, без блокировки чтения);
`CopyOnWriteArrayList`; блокирующие очереди `ArrayBlockingQueue`, `LinkedBlockingQueue`;
`ConcurrentLinkedQueue`.

Графика: схема `ConcurrentHashMap` (бакеты из занятия 6 + замок на бакет); таймлайн
producer/consumer через очередь.

Код: гонка в `HashMap` (показать симптом); `ConcurrentHashMap` в примере-счётчике слов;
producer–consumer на `ArrayBlockingQueue`.

### 8. Пулы потоков и ExecutorService (10–12 слайдов)

Тезисы: почему создавать `Thread` дорого; `ExecutorService`, `Executors.newFixedThreadPool /
newCachedThreadPool / newSingleThreadExecutor`; `ScheduledExecutorService`; очередь задач
и отказ (`RejectedExecutionHandler`); правило «пул под задачу»: CPU-bound vs IO-bound,
формула числа потоков; `shutdown`/`shutdownNow`/`awaitTermination`.

Графика: схема «пул + очередь задач + N воркеров»; таблица видов пулов.

Код: пакетный расчёт в `FixedThreadPool`; сравнение времени одного потока против пула;
корректное завершение пула.

### 9. Future и CompletableFuture (10–12 слайдов)

Тезисы: `Future.get` — блокирующий результат; `CompletableFuture`: `supplyAsync`,
`thenApply/thenAccept/thenCompose`, комбинирование `thenCombine`, `allOf/anyOf`;
обработка ошибок `exceptionally/handle`; цепочки против вложенных колбэков.

Графика: диаграмма цепочки стадий (аналог конвейера из занятия 14); таймлайн двух задач
последовательно против параллельно.

Код: `Future` на `submit`; цепочка `CompletableFuture` «скачать → распарсить → свернуть»;
`allOf` для параллельных запросов; сравнение времени.

### 10. Обедающие философы (10–12 слайдов)

Тезисы: постановка задачи — 5 философов, 5 вилок; дедлок при жадном захвате; решения:
нумерация ресурсов и захват «младшей вилки сначала», ограничение числа сидящих (семафор),
централизованный официант, tryLock с откатом; связь с реальными системами (блокировки
транзакций).

Графика: классическая картинка круглого стола; пошаговый таймлайн дедлока; те же шаги
с нумерацией вилок — дедлок исчезает.

Код: `Philosopher`, `Fork` как `ReentrantLock`; воспроизводимый дедлок и три решения
(порядок, семафор, tryLock с таймаутом); прогон на пуле потоков.

### 11. Виртуальные потоки (8–10 слайдов)

Тезисы: платформенный против виртуального потока; carrier-потоки ForkJoinPool; дешёвость
блокировки вместо её избегания; `Thread.ofVirtual`, `Executors.newVirtualThreadPerTaskExecutor`;
когда виртуальные потоки помогают (IO-bound) и когда нет (CPU-bound, pinning);
взаимодействие с пулами и `ThreadLocal`.

Графика: схема «миллионы виртуальных на нескольких carrier»; сравнение платформенных
и виртуальных потоков таблицей.

Код: пример из документации — 100 000 виртуальных потоков против пула (с оговоркой про JDK,
см. открытые вопросы).

### 12. Потокобезопасность: паттерны и принципы (10–12 слайдов)

Тезисы: самый надёжный код — без общего состояния; неизменяемость (final-поля,Immutable-объекты
из занятия 12); confined-объекты и передача владения; confinement через `ThreadLocal`;
message passing — акторы/очереди вместо замков; документирование контрактов
(`@NotThreadSafe`/`ThreadSafe`); чек-лист «проверь гонку, дедлок, видимость».

Графика: таблица «приём → когда применять»; схема message passing против общего состояния.

Код: неизменяемый объект как безопасный результат `Future`; переписывание примера с общим
счётчиком на обмен сообщениями через очередь.

### 13. Сводка и практика (4–6 слайдов)

Тезисы-итоги по всем разделам (одна таблица «проблема → инструмент»); слайд «Programming Time!»;
задания практики (ниже).

## Модуль практики

Новый модуль `17-concurrency` (артефакт `17-concurrency`, описание «Модуль №17.
Многопоточность»), пакет `ru.mifi.practice.vol17` — по образцу `06-hashing` и `16-mazes-life`:
отдельный `pom.xml` с зависимостью на `00-commons`, `README.md`, примеры в `src/main/java`,
«злые» тесты в `src/test/java` один-к-одному. Регистрация модуля в корневом `pom.xml`.

Пакеты и примеры (каждому разделу лекции — свой):

| Пакет | Примеры |
|---|---|
| `vol17.thread` | `HelloThread` (start/run/join), `InterruptibleTask` (отмена), `StatefulThread` (состояния) |
| `vol17.race` | `BrokenCounter` (гонка), `VolatileCounter`, `HappensBefore` |
| `vol17.monitor` | `ProducerConsumer` (wait/notify на кольцевом буфере) |

починить `BrokenCounter`, реализовать producer–consumer на `wait/notify`, убрать дедлок
у философов, переписать вложенные `Future.get` на `CompletableFuture`.

## Послайдовая логика (пример на разделе 3)

1. Слайд «Гонки данных и JMM» — титульный.
2. Тезис 1: «оператор ++ — это чтение, сложение и запись».
3. Тезисы 1–2: тезис 1 + «два потока читают одно и то же старое значение».
4. Тезисы 1–3: + «результат зависит от interleaving — гонка».
5. Тезисы 1–4: + «JMM: без синхронизации запись может быть не видна».
6. Тезисы 1–5: + «happens-before задаёт порядок видимости».
7. Тезисы 1–6: + «volatile — видимость, но не атомарность».
8. Графика: пошаговая таблица interleaving с числами.
9. Код: `BrokenCounter` из практики.
10. Сводка раздела.

Остальные разделы — та же схема: титул → потезисное раскрытие → графика → код → сводка.

## Открытые вопросы к заказчику

1. **«luma» в постановке.** В списке тем значится «luma». Я не нашёл однозначной трактовки:
   это LMAX Disruptor (lock-free очередь), Loom (виртуальные потоки — тогда дубль) или что-то
   третье? В план Disruptor не включён, Loom включён как раздел 11. Требуется уточнение.
2. **JDK и виртуальные потоки.** Проект собирается на JDK 17 (enforcer), виртуальные потоки
   стабильны с JDK 21. Варианты: (а) раздел 11 теоретический, без компилируемого кода;
   (б) пример под `--release 21` с оговоркой и пометкой; (в) поднять JDK проекта. Нужно решение.
3. **Номер занятия.** Курс рассчитан на 16 занятий, лекция становится занятием 17
   (соответственно модуль `17-concurrency`). Подтвердить или указать другое место.
4. **Объём.** 90–110 слайдов на 13 разделов — ок или сжать/расширить? Какие разделы приоритетны
   для заказчика, если нужно резать объём?
5. **Демонстрации.** Гонки и дедлоки недетерминированы: в практике — цикл повторений с
   утверждением «хотя бы один раз», на слайдах — псевдослучайные, но фиксированные сценарии
   interleaving с числами. Приемлемо?
