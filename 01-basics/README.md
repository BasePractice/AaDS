# Разделы 1–2. Асимптотика и линейные структуры данных

| Пакет | Тема |
|---|---|
| `bigo` | классы сложности: O(1), O(log n), O(n) на живых примерах |
| `array` | динамический массив: `StandardArray` на массиве, `LinkedArray` на двусвязном списке |
| `stack` | стек LIFO поверх `Array` |
| `queue` | очередь FIFO поверх `Array` |
| `cbs` | правильная скобочная последовательность — стек в деле |
| `rpn` | обратная польская запись — снова стек |

Сортировки для сравнения по числу шагов лежат в `05-sorting-search` (`MainSort`), наивный Фибоначчи
со счётчиком вызовов — в `13-dynamic-programming` (`Fibonacci.Recursion`).

## Стоимость операций

| Операция | Массив | Список |
|---|---|---|
| `get(i)` | O(1) | O(n) |
| `set(i)` в конец | O(1) амортизированно | O(1) |
| `delete(i)` | O(n), сдвиг | O(n) на поиск, O(1) на связывание |

Очередь построена поверх массива, поэтому `dequeue` сдвигает весь массив за O(n).
Кольцевой буфер, дающий O(1), лежит в `90-sandbox` в пакете `buffer`.

## Практика по амортизационному анализу

1. Создайте пустой `StandardArray<Integer>` с ёмкостью 1 и добавьте числа от 0 до 8
   через `addLast`. Сравните `copies()` до и после каждой вставки в тесте
   пакета `ru.mifi.practice.vol1.array`. Счётчик учитывает длину старого массива
   при расширении. Проверьте, что все числа читаются в исходном порядке.
2. Для роста на одну ячейку запишите, сколько ячеек нужно копировать на каждой
   вставке после первой. Сложите эти числа. Повторите сравнение для миллиона
   вставок. Для роста на единицу вычислите сумму в `long` по формуле `m(m−1)/2`.

Из корня репозитория на JDK 17:

```sh
mvn -B -pl 01-basics -am -Dtest=ArrayGrowthTest -Dsurefire.failIfNoSpecifiedTests=false test
```

| Добавлений | Копирования при удвоении | Копирования при росте на 1 |
|---:|---:|---:|
| 9 | 15 (1, 2, 4 и 8) | 36 |
| 1 000 000 | 1 048 575 | 499 999 500 000 |

Каждое добавление также записывает новый элемент. Для девяти добавлений
при удвоении получаем 15 + 9 = 24 операции в этой модели.
